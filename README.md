# أَثَر 87 | ATHAR 87

منصة المدرسة الثانوية 87 لتوثيق السلوك المتميز لدى الطالبات وشواهده، ببوابتين منفصلتين: بوابة الطالبة وبوابة المتحكم.

## المتطلبات
- Node.js ‎22.5 أو أحدث (يعمل بلا أي حزم خارجية: `node:http` و`node:sqlite` و`crypto`).
- لا حاجة إلى `npm install`.

## التشغيل
```bash
npm run create-admin      # إنشاء أول متحكم (تفاعلي) أو عبر ADMIN_USERNAME / ADMIN_PASSWORD / ADMIN_FULL_NAME
npm start                 # يعمل على http://localhost:3000 (المتغير PORT)
npm test                  # 15 اختبار واجهة برمجية
```
لا توجد كلمات مرور افتراضية: أول حساب يُنشأ بأمر `create-admin` فقط.

## قاعدة البيانات والملفات
- قاعدة SQLite في `data/athar.db` (تُنشأ وتُهيّأ تلقائيًا مع البيانات الرسمية: 3 مراحل بـ 5/5/4 فصول، 5 فئات، 15 بندًا بدرجاتها).
- الملفات المرفوعة خاصة في `data/uploads/<رقم الطالبة>/` ولا تُخدم إلا عبر مسار يتحقق من الصلاحية.
- مسارات قابلة للتغيير بمتغير `DATA_DIR`.

## الاستخدام اليومي
- **إضافة طالبات:** المتحكم ← إدارة الطالبات ← إضافة، أو استيراد CSV. يُولَّد اسم المستخدم (S0001، S0002…) وكلمة مرور مؤقتة تُعرضان مرة واحدة. أعمدة CSV: الاسم، المرحلة، الفصل (عمود اسم المستخدم اختياري)، وتُجبَر الطالبة على تغييرها عند أول دخول.
- **تسجيل الطالبات بأنفسهن:** من صفحة «إنشاء حساب جديد». تتحكم الإدارة من إعدادات المنصة (تشغيل/إيقاف، ورمز تسجيل اختياري يُنصح به لمنع تسجيل غير الطالبات).
- **المراحل والفصول:** من إعدادات المنصة (إضافة فصل، نقل طالبة بين الفصول مع حفظ السجل).
- **البنود:** إدارة البنود لتعديل الاسم والوصف والتعليمات والتفعيل والترتيب.
- **المراجعة:** مراجعة الشواهد ← تغيير الحالة (قيد المراجعة / مقبول / يحتاج إلى استكمال) مع ملاحظة تظهر للطالبة. اعتماد الدرجة خطوة منفصلة ولا يتم إلا بعد القبول، وضمن درجة البند. بند «السلوك الإضافي» يتطلب توصية اللجنة. أي تعديل من الطالبة يعيد المشاركة إلى «قيد المراجعة» ويسحب الدرجة.
- **الدرجات:** المحددة للبند، والمعلّقة، والمعتمدة منفصلة. لا يوجد سقف كلي افتراضي؛ يمكن تحديد قواعد المجموع من الإعدادات.
- **الأدوار:** متحكم (كل الصلاحيات) ومراجعة (مراجعة وملاحظات فقط).
- **التقارير:** تقارير الطالبات/البنود/الإدارة، تصدير Excel، وحفظ PDF عبر الطباعة.
- **سجل العمليات** للأحداث المهمة، و**سياسة الخصوصية** قابلة للتعديل.

## النسخ الاحتياطي والاحتفاظ
```bash
npm run backup   # نسخة من القاعدة والملفات في data/backups (يحتفظ بآخر 14)
npm run purge    # حذف نهائي للملفات المحذوفة بعد مدة الاحتفاظ (الافتراضي 90 يومًا)
```
يُنصح بجدولتهما (cron). للاستعادة: أوقفي الخادم وأعيدي ملف القاعدة ومجلد uploads.

## النشر
- شغّليه خلف وكيل عكسي بـ HTTPS (nginx/Caddy) مع `NODE_ENV=production` و`TRUST_PROXY=1` (يفعّل ملف تعريف `__Host-` وSecure).
- قرص دائم لمجلد `data/`.
- اختياري: `CLAMSCAN_PATH` لفحص الملفات بـ ClamAV.
- الشعار: استبدلي `public/assets/logo.svg` بالشعار المعتمد. الخط: ضعي ملفات الخط في `public/css/fonts.css` إن رغبتِ.

## الخط
يُحمَّل خط IBM Plex Sans Arabic من Google Fonts (يحتاج اتصال إنترنت للمتصفح). للعمل دون اتصال خارجي نزّلي ملفات الخط وضعيها محليًا في `public/fonts` وعرّفيها في `public/css/fonts.css`، ثم أزيلي رابط Google من `index.html` و`404.html` والنطاقين من سياسة CSP في `src/http.js`.

## الأمان المطبّق
تجزئة scrypt، جلسات بمعرّف مُجزَّأ، قفل الحساب وتحديد المحاولات، حماية CSRF، رؤوس CSP، تحقق من نوع الملف بالبايتات الأولى (JPG/PNG/PDF/DOCX/PPTX)، صلاحيات على الخادم لكل طلب، وإرجاع 404 لملفات غيرك.

## حدود وأمور غير مكتملة (بصراحة)
- لا يوجد Supabase/Firebase؛ التخزين محلي (SQLite وقرص الخادم).
- لا فحص فيروسات افتراضيًا (يتطلب تثبيت ClamAV).
- PDF عبر طباعة المتصفح، لا توليد خادمي.
- ملفات DOCX/PPTX تُنزَّل فقط ولا تُعاين في المتصفح.
- تحديد المحاولات في الذاكرة (يُعاد ضبطه عند إعادة التشغيل، ولا يصلح لعدة نسخ).
- `node:sqlite` ما زال تجريبيًا في Node.
- نص سياسة الخصوصية الافتراضي مقترح ويجب اعتماده من إدارة المدرسة والجهة المختصة؛ لا تدّعي المنصة شهادة امتثال لنظام حماية البيانات الشخصية.
- لم تُختبر جميع معايير القبول الـ 46 اختبارًا آليًا كاملًا؛ غُطّي منها الجانب الخلفي (15 اختبارًا) وفحص واجهة آلي بلا أخطاء، وتبقى مراجعة يدوية على أجهزة حقيقية.
